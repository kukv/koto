# 承認根拠の記録と review_notes の役割分離 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 承認が「未解決の確認事項は解決した」ことを表せるようにし、何を根拠に承認したかを記録に残す。

**Architecture:** `knowledge` に `verified_note` 列を 1 つ足し、`verified_by` / `verified_at` / `verified_note` を常に同じ判定の組として扱う。この組を書くのは `approve` と `setVerification` の 2 経路だけで、どちらも `review_notes` を `null` にする。`review_notes` は「未解決の確認事項」専用になる。根拠はエージェントが MCP ツールの必須引数として書き、確認ダイアログに表示して人間が見てから判定する。

**Tech Stack:** PostgreSQL 18.4 / PGroonga 4.0.8 / pgvector 0.8.6 / TypeScript / node-postgres / vitest / @modelcontextprotocol/sdk

設計の根拠は `docs/superpowers/specs/2026-08-10-承認根拠の記録-design.md` を参照。

### 背景

`v_knowledge_approved` は `select * from knowledge where status = 'approved'` で定義されているが、Postgres はビュー作成時に `*` を列リストへ展開して固定する。そのため `alter table ... add column` しても既存ビューに新しい列は現れない。一方 `001_schema.sql` はテーブルの後にビューを作るので、新規 DB のビューには `verified_note` が入る。マイグレーションでビューを作り直さないと、稼働中 DB と新規 DB でビューの列が食い違う。

docker exec -i koto-db-1 psql -U koto -d koto -c "create database koto_mig_check"
git show HEAD:docker/db/init/001_schema.sql | docker exec -i koto-db-1 psql -U koto -d koto_mig_check -v ON_ERROR_STOP=1

docker exec -i koto-db-1 psql -U koto -d koto -c "create database koto_fresh_check"
docker exec -i koto-db-1 psql -U koto -d koto_fresh_check -v ON_ERROR_STOP=1 < docker/db/init/001_schema.sql

両方の列構成を比べる。

```typescript
export async function approve(
  id: string,
  by: string,
  note: string,
  expectedUpdatedAt: string,
) {
  const res = await pool.query(
    `update knowledge
        set status = 'approved', needs_review = false, review_notes = null,
            verification = case when verification = 'expert' then 'expert' else 'internal' end,
            verified_by = $2, verified_at = now(), verified_note = $3
      -- pg ドライバは timestamptz を ms 精度の Date で返すため、DB 側も ms に丸めて比較する
      where id = $1 and date_trunc('milliseconds', updated_at) = $4::timestamptz`,
    [id, by, note, expectedUpdatedAt],
  );
  if (res.rowCount === 0) await throwOptimisticLockError(id);
  return { id, status: "approved" as const };
}
```

 * レビューを通して承認する(検索の既定対象になる。検証レベルは internal、既に expert なら維持)。
