# owner 未設定の承認警告 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 承認責任者(`contexts.owner`)が決まっていない領域の知識を承認・却下・検証しようとしたとき、確認ダイアログでそれを人に伝える。

**Architecture:** `contexts` から owner を 1 件引く関数を core に足し、確認ダイアログの材料を組み立てる `reviewTarget` がそれを詰める。ダイアログ本文の組み立て(`elicit.ts`)で owner が null のときだけ警告行を挟む。承認・却下・検証は同じ `requireHumanApproval` を通るので、1 か所に入れれば 3 つとも揃う。実行は止めない。

**Tech Stack:** TypeScript / node-postgres / vitest 4 / @modelcontextprotocol/sdk

設計の根拠は `docs/superpowers/specs/2026-08-12-owner未設定の承認警告-design.md` を参照。

## Global Constraints

- パッケージ管理は **pnpm**。`npm` は使わない
- **この worktree で DB を新たに立てない。** メインチェックアウトの `koto-db-1` が port 5432 で稼働しており衝突する。worktree からは `docker compose` のプロジェクト名がずれるため使わない。DB を直接見るときは `docker exec -i koto-db-1 psql -U koto -d koto`
- **本番 DB(`koto`)に書き込まない。** テストは `koto_test` を使う。テストヘルパー(`packages/core/tests/helpers/db.ts` と `packages/mcp-server/tests/helpers/db.ts`)は `DATABASE_URL` が `/koto_test` で終わらなければ例外を投げるガードを持つ
- vitest の設定はリポジトリのルートにあり、パッケージ単位では走らない。1 ファイルを流すのは `pnpm exec vitest run <ファイルパス>`
- 統合テストの実行には DB が起動している必要がある(globalSetup が `koto_test` を作り直す)
- **スキーマ(`docker/db/init/` `docker/db/migrations/`)には一切触れない。** `contexts` の定義は変えない
- **ツールの引数・戻り値・説明文は変えない。** 変わるのはダイアログ本文だけ
- 警告文は `⚠ この領域には承認責任者(owner)が未設定です` の **1 行のみ**。`upsert_context` で設定できる、といった操作案内はダイアログに入れない
- 警告はレコード行(`[<type>/<context>] <title> (status: <status>)`)の**直後**に置く。レコード情報は ID 取り違えの最終防波堤なので、下に押し下げない
- `packages/mcp-server/src/server.ts` の `reviewTarget` 以外の関数には触れない
- 各タスクの最後に `pnpm run lint:fix` を実行してから commit する

```ts
/**
 * コンテキストの承認責任者。未設定・未登録なら null。
 * 承認ダイアログで「誰がこの知識の正しさを判定できるか」が未定義であることを警告するために使う。

export async function contextOwner(name: string): Promise<string | null> {
  const res = await pool.query(`select owner from contexts where name = $1`, [name]);
  return (res.rows[0]?.owner as string | null) ?? null;
}
```

```ts
/** 確認ダイアログに出す最小情報を取り出す(見つからなければ null) */
async function reviewTarget(id: string): Promise<ReviewTarget | null> {
  const rec = await getKnowledge(id, false);
  if (!rec) return null;
  const updatedAt =
    rec.updated_at instanceof Date ? rec.updated_at.toISOString() : String(rec.updated_at);
  return {
    id,
    type: String(rec.type),
    context: String(rec.context),
    title: String(rec.title),
    body: String(rec.body),
    status: String(rec.status),
    context_owner: await contextOwner(String(rec.context)),
    review_notes: rec.review_notes == null ? null : String(rec.review_notes),
    english_name_conflicts: await findEnglishNameConflicts(id),
    updated_at: updatedAt,
  };
}
```
